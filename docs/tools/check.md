# 쓰는 중에 점검받기

| | |
|---|---|
| **명령** | `/portfolio-check [폴더]` · 말로 해도 됨 — "프로젝트 문서 점검해 줘", "무슨 자료가 더 필요해?" |
| **언제 쓰나** | 프로젝트 문서를 쓰는 중에 여러 번. 문서를 쓰기 전에 실행하면 무엇을 준비해야 하는지 알려 줍니다 |
| **바뀌는 것** | `report.md`만. 프로젝트 문서와 `data/`는 건드리지 않습니다. 폴더 이름을 빼면 모든 프로젝트를 봅니다. |
| **되돌리기** | 필요 없습니다. `report.md`는 실행할 때마다 다시 쓰입니다 |

```text
/portfolio-check 1-my-game
```

## 무엇을 점검하나요

- 프로젝트 문서를 가이드 기준(5단 구조·포트폴리오 체크리스트·다이어그램)으로 점검해, 항목마다 **어디가 / 무엇이 부족하고 / 왜 중요한지 / 어떤 방향으로**를 알려 주고 잘한 점도 짚어 줍니다. 고친 문장을 대신 써 주지는 않습니다.
- **내용**: 읽는 사람이 찾는 답 여섯 가지가 문서에 있는지 봅니다 → [읽는 사람은 무엇을 보나요](../1-portfolio.md#읽는-사람은-무엇을-보나요)
- **구조**: 개요가 게임 개발을 모르는 사람에게도 읽히는지, 소제목이 바로 읽히는지, 같은 내용을 반복하지 않는지 봅니다 → [칸마다 쓰는 법](../3-writing.md#칸마다-쓰는-법)
- 다이어그램은 **종류가 설명하는 것과 맞는지**도 봅니다(예: 데이터 필드를 플로우차트로 그렸으면 ERD, 여러 클래스의 호출 차례를 플로우차트로 그렸으면 시퀀스). 안 맞으면 권장입니다.
- 빠진 다이어그램과 종류를 바꿀 다이어그램은 Claude에게 그대로 부탁할 수 있는 **요청 문장**(코드의 실제 이름을 채운)으로 제안합니다.
- 슬라이드에서 작아지거나 나뉠 곳(노드가 많은 다이어그램, 20줄 넘는 코드)도 미리 **참고**로 알려 줍니다.
- 이미지 경로의 대소문자, 빈 링크, `code/`와 문서 코드가 맞는지도 확인합니다.

## 재료 점검표

문서가 아직 없거나 뼈대의 칸이 비어 있으면, 칸마다 **있음 · 부족 · 없음**과 그 칸을 쓰는 데 필요한 자료, 구하는 법을 표로 알려 줍니다. 문서를 쓰기 전에 실행해도 됩니다(칸마다 필요한 자료는 [format/07-materials.md](../../format/07-materials.md)).

```markdown
## 재료 점검표
### Switch Strike (`src/1-action-platformer/`)
프로젝트 문서: 있음 · 이미지 2장 · code/ 없음 · 재료집: 푼 질문 3 / 19

| 칸 | 상태 | 지금 있는 것 | 더 필요한 것 | 구하는 법 |
|---|---|---|---|---|
| 개요 — 무엇을·왜 | 있음 | 문서 §1 | — | — |
| 개요 — 목표한 경험 | 없음 | — | 컨셉기획서, 기획 발표 자료 | "이 게임을 한 사람이 끝나고 뭐라고 말하면 성공인가?"에 한 문장으로 답하기 |
| 기능 단위 — 구현 | 부족 | 재료집 3번 질문 2/3 | 핵심 코드, 구조 그림 | `/portfolio-intake <레포 주소>` |
| 화면 | 부족 | 2 / 4장 | 스크린샷·GIF 2장 이상 | `_intake/촬영목록.md`대로 찍기 |
```

- 상태는 **세거나 찾을 수 있는 것**으로만 정합니다: 문서에 그 내용이 있는지, 재료집에서 답한 질문 수, 이미지 수와 `code/` 유무.
- 문서가 없거나 꼭 필요한 칸이 비어 있으면, 가진 자료(기획서, AI 대화 기록, 플레이테스트 메모 등)를 한 번에 모아 묻습니다.
- 자료가 있어도 그 내용으로 문서를 대신 쓰지 않습니다. 무엇을 어디에 두고 어느 칸에 쓰는지만 알려 줍니다.

## 리포트

지적은 세 등급입니다. **필수**(없으면 포트폴리오의 목적을 이루지 못함) · **권장**(있으면 확실히 좋아짐) · **참고**(다듬기와 알아 두면 좋은 것). 필수부터 0으로 만듭니다.

```markdown
## 프로젝트별 점검
### Switch Strike (`src/1-action-platformer/프로젝트문서.md`)
- **[권장]** 문제 해결 사례(§2.8·§2.9·§3.6·§3.8·§6.7)에 해결 뒤 달라진 점이 없습니다 (기준: format/01 이슈 해결 사례) → 방향: 고친 뒤 재현 여부나 달라진 점을 한 줄씩.
- **[권장]** 같은 내용이 여러 곳에 반복됩니다 — §1 둘째 문단 ↔ §3 도입, §8.2 ↔ §8.3 (기준: format/02 문서 구조) → 방향: 한 곳에 쓰고 나머지는 가리키기.
- **[참고]** 있으면 좋은 항목 중 레퍼런스(참고한 게임과 다른 점)·조작법이 없습니다.
- 👍 목표한 경험·AI 협업·회고가 모두 구체적이고, 소제목에 틀 이름이 없습니다.
```

리포트의 절마다 무엇이 있는지는 [포트폴리오 만들기](build.md#포트폴리오-만들기)에 있습니다. 점검만 했을 때는 그중 "확인해 주세요"와 "장면 점검"이 빠집니다.
