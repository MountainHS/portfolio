# 페이지 만들기

| | |
|---|---|
| **명령** | `/portfolio-build [폴더]` · 말로 해도 됨 — "포트폴리오 만들어 줘" |
| **언제 쓰나** | 프로젝트 문서를 처음 넣었을 때, 그리고 프로젝트 문서나 `profile.md`를 고친 뒤마다 |
| **바뀌는 것** | `data/`, `report.md`. 폴더 이름을 주면 그 프로젝트만 다시 만듭니다. |
| **되돌리기** | 다시 실행하면 `data/`를 새로 만듭니다. 틀린 곳은 `data/`가 아니라 원본(`src/`·`profile.md`)을 고칩니다 |

`profile.md`를 채우고 `/portfolio-build`로 세 페이지의 데이터를 만든 뒤 미리보기로 확인하는 과정입니다.

## profile.md 채우기

`profile.md`는 **여러분이 직접** 씁니다. 들어 있는 값(홍길동, `you@example.com` 등)은 예시이니 모두 내 정보로 바꾸세요(예시 그대로면 리포트 **필수**). 비워 둔 항목은 페이지에 나오지 않습니다.

| 항목 | 어디에 쓰이나요 | 메모 |
|---|---|---|
| 이름 · 영문 이름 · 한 줄 정체성 | 포트폴리오 페이지 머리 | |
| 이메일 · GitHub · 기타 링크 | 머리 · 연락처 | |
| 자기소개 | 자기소개 절 | 2~3문장. Claude가 고쳐 쓰지 않고 줄바꿈까지 그대로 싣습니다 |
| 기술 스택 메모 (선택) | 기술 스택 절 | 적은 기술마다 Claude가 프로젝트 문서에서 **근거를 찾아** "경험 기반" 문장으로 만듭니다. 근거를 못 찾은 기술은 싣지 않고 리포트로 알립니다. 비우면 문서에서 자동으로 고릅니다 |
| 강조색 | 버튼 · 링크 · 태그 | `#2F6FEB`처럼 색 코드 하나 |
| 프로젝트 순서 | 실리는 프로젝트와 순서 | 비우면 `src/` 폴더 이름 순서. 순서를 정하거나 일부만 싣고 싶을 때만 폴더 이름을 쉼표로(예: `2-my-rpg, 1-my-game`). 대소문자까지 정확히 |
| 구성 방식 | — | `project`(프로젝트 중심) / `stack`(기술 스택 중심). **지금의 포트폴리오 페이지에는 아직 반영되지 않습니다** |

> 이 레포는 공개라서 `profile.md`의 내용은 누구나 볼 수 있습니다. 전화번호·주소 같은 개인정보는 넣지 마세요.

## 포트폴리오 만들기

"포트폴리오 만들어 줘"라고 말해도 됩니다. 프로젝트 하나만 다시 만들 때는 `/portfolio-build 1-my-game`. Claude가 하는 일은 [포트폴리오 데이터 만들기](#포트폴리오-데이터-만들기)에 있습니다.

```text
/portfolio-build
```

끝나면 **`report.md`를 꼭 읽으세요.**

| 절 | 무엇인가요 | 어떻게 하나요 |
|---|---|---|
| 요약 | 프로젝트마다 필수·권장·참고 개수, 스크린샷 수, 링크 상태 | **필수**부터 0으로 만듭니다 |
| **확인해 주세요** | Claude가 원문을 **줄여서 만든 문장** 목록(한 줄 소개, 기술 스택 근거, 슬라이드 글 등) | 내 의도와 맞는지 **직접** 확인합니다. 다르면 원문을 고치고 다시 빌드 |
| 프로젝트별 점검 | 가이드 기준 점검(어디가 / 무엇이 / 왜 / 어떤 방향으로) | 프로젝트 문서를 고칩니다 |
| 장면 점검 | 미리보기에서 잰 배치 문제(잘린 장면, 작은 다이어그램, 빈 장면, 나뉜 코드). 장이나 절이 많아 장면을 줄였으면 「장면 고르기」에 장마다 무엇을 남겼고 이전 판의 어떤 장면이 빠졌는지 | 프로젝트 문서를 고치거나 `/portfolio-edit` |
| 프로필 · 다음 할 일 | `profile.md` 문제와 먼저 할 일 | |

등급은 셋입니다. **필수**(없으면 포트폴리오 목적을 못 이룸 — 배포된 페이지에 빨간 띠가 보이는 문제도 여기) · **권장**(있으면 확실히 좋아짐) · **참고**(다듬기와 알아 두면 좋은 지표).

- 틀린 곳은 `data/`가 아니라 **원본(`src/`, `profile.md`)을 고친 뒤** 다시 `/portfolio-build` 하세요. `data/`를 손으로 고치면 다음 빌드에 사라집니다.
- 슬라이드의 **장면 하나만** 다르게 보이고 싶다면(그림을 크게, 다른 그림으로, 둘로 나누기, 빼기 등) → [슬라이드 장면 고치기](edit.md#슬라이드-장면-고치기)
- 페이지의 **절 이름·버튼 문구**를 내 말로 바꾸고 싶다면 → [문구 바꾸기](design.md#문구-바꾸기)

## 포트폴리오 데이터 만들기

- **고칠 곳은 원본**: 틀린 곳은 `src/`·`profile.md`를 고치고 다시 실행합니다. 리포트 읽는 법은 [포트폴리오 만들기](#포트폴리오-만들기)에 있습니다.
- 다시 빌드해도 같은 절을 다루는 슬라이드 장면의 주소(`#s=…`)는 그대로입니다.

### Claude가 하는 일

1. `src/`의 프로젝트 문서를 끝까지 읽고, 포트폴리오 페이지에 넣을 요약(한 줄 소개·개발 의도·핵심 구현·트러블슈팅·스크린샷)과
   슬라이드의 장면 목록(어느 절의 어떤 그림·코드·표를 보일지)을 골라 `data/`에 정리합니다.
   그림·코드·표는 옮겨 적지 않고 **원문을 가리키기만** 합니다(페이지가 프로젝트 문서에서 그대로 가져와 그림).
2. 쓰기 전에 검증합니다 — 이미지 파일이 대소문자까지 실제로 있는지, 절 제목이 원문에 있는지, "원문 그대로"라고 표시한 글이 정말 원문에 있는지 등.
3. `/portfolio-edit`로 고쳐 둔 슬라이드 장면이 있으면 다시 반영합니다.
4. 미리보기를 띄워 깨진 이미지·잘린 장면·작은 다이어그램을 재고, <b>`report.md`</b>를 씁니다.

## 미리보기

`data/`와 프로젝트 문서를 불러와 그리는 방식이라 **파일 더블클릭으로는 열리지 않습니다.** 아래 중 하나로 여세요.

```bash
python -m http.server 4600
```

→ http://localhost:4600 (Windows에서 `python`이 없으면 `py -m http.server 4600`)

- Claude 데스크톱 앱: 미리보기에서 `portfolio` 구성을 고르거나, Claude에게 "미리보기 띄워줘"

처음 열리는 것은 포트폴리오 페이지(`index.html`)이고, 슬라이드·상세 문서는 그 안의 링크로 열립니다(주소를 직접 치려면 `project.html?p=폴더 이름`, `doc.html?p=폴더 이름`).
고친 것이 안 보이면 **Ctrl+F5**로 새로 고치세요. 슬라이드에 빨간 띠·노란 띠·빨간 숫자가 보이면 [문제 해결](../troubleshooting.md#문제-해결)을 보세요.
