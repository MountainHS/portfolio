# 기술문서 고민 정리 키트

> **AI에게 먼저 보여 줄 파일:** [AI-GUIDE.md](AI-GUIDE.md)
> 이 README는 사람이 읽는 소개입니다. 설치와 실행 규칙은 AI가 [AI-GUIDE.md](AI-GUIDE.md)를 읽고 맡습니다.

이 키트는 포트폴리오 기술문서를 AI와 함께 쓸 때 **내가 실제로 한 고민을 지키는** 작업 방식과 도구 묶음입니다.

## 왜 만들었나

AI에게 기술문서를 맡기면 고민의 흔적이 사라집니다. 문서는 깔끔해지지만 다음 내용이 빠집니다.

- 처음에 무엇을 문제로 보았는지
- 검토했다가 버린 방법
- 실패한 시도와 판단을 바꾼 순간
- AI에게 무엇을 시켰고 결과를 어떻게 고쳤는지

면접관은 바로 이 부분을 묻습니다.

그래서 이 키트는 고민부터 꺼내 정리하고, 그다음에 문서로 옮깁니다. 고민을 꺼내는 곳은 **원천 자료**입니다. 원천 자료는 작업하며 남긴 메모·회고·일정 기록·발표 자료처럼 문서를 쓰기 전의 기록을 말합니다.

## 실제로 해 본 결과

Unity 팀 프로젝트 두 개에 써 봤습니다.

| 프로젝트 | 찾은 고민 | 답을 단 횟수 | 끝난 뒤 |
|---|---|---|---|
| 네트워크 협동 게임 | 29개 (대표 사례 4개) | 4번 | 남은 질문 0개, 문서에 반영 |
| FPS 몬스터·웨이브 | 33개 (대표 사례 5개) | 2번 | 남은 질문 0개, 문서에 반영 |

문서에 없던 고민이 여러 개 다시 들어갔습니다. "처음엔 이 방식이었다가 왜 바꿨나", "고치지 못한 버그를 어떻게 예방했나" 같은 것입니다.

그때 만든 실제 파일은 `examples/` 폴더에 있습니다. 고민을 큰 것·중간·작은 것으로 나누는 기준과, 고민 하나가 원천 자료 한 줄에서 기술문서 한 절이 되기까지의 실제 기록은 [고민-레벨과-구체화-예시.md](고민-레벨과-구체화-예시.md)에 있습니다.

## 전체 흐름

```
① 준비          원천 자료 고르기 → AI가 초안과 질문을 씀
      ↓
② 고민 분류      AI가 고민을 찾아 큰 것·중간·작은 것으로 나눔
      ↓
③ 답 달기        내가 질문 아래에 답을 씀 (여러 번 반복)
      ↓
④ 대화 세션      기억이 흐린 질문은 AI와 코드를 같이 보며 따로 이야기
      ↓
⑤ 문서에 반영    정리된 고민을 기술문서의 알맞은 자리로 옮김
      ↓
⑥ 퇴고·피드백    새 초안 섞기, 흐름 다듬기, 멘토 피드백 반영
      ↓
⑦ 점검          빠진 것이 없는지 마지막 확인
```

- ①은 문서가 아직 없을 때만 합니다. 문서가 이미 있으면 ②부터 시작합니다.
- 내 손이 가장 많이 가는 단계는 ①·③·④입니다. 나머지는 AI가 하고 나는 결과를 확인합니다.
- **세션**은 AI와 나누는 대화 한 번(대화 창 하나)을 말합니다.

## 내가 직접 하는 일

AI가 대부분을 하고, 아래 다섯 가지는 내가 합니다.

**1. 원천 자료 고르기**
- AI가 파일 목록을 보여 주면 읽을 것을 고릅니다.
- AI는 고른 자료만 봅니다.
- 팀원 개인 평가나 비밀번호가 든 파일은 뺍니다.

**2. 질문 아래에 답 달기**
- AI는 찾은 고민을 **정리 파일** 하나에 모읍니다. 질문은 그 파일 맨 앞에 있습니다.
- 질문 바로 아래 줄에 **Tab 키로 들여써서** 답을 씁니다.
- 기억나는 만큼만 씁니다. "모르겠음"도 답입니다.
- "나중에"나 "후순위"라고 쓰면 그 질문은 보류됩니다.

**3. 정리 파일은 옵시디언(Obsidian)으로 보기**
- 옵시디언은 메모 파일을 읽고 쓰는 무료 프로그램입니다.
- 정리 파일은 접고 펼치는 상자와 파일 사이 링크를 씁니다. 옵시디언에서 열어야 이것이 제대로 보입니다.

**4. 세션 넘기기**
- 답을 다 달았거나 대화가 길어지면 "새 세션에서 이어서 해 줘"라고 말합니다.
- AI가 다음 세션이 이어 갈 수 있게 정리해 둡니다.

**5. 어려운 질문은 따로 이야기하기**
- 정말 기억나지 않는 질문은 "이 질문은 따로 대화 세션 열어 줘"라고 말합니다.
- AI가 그 부분 코드를 보여 주며 하나씩 물어봅니다.

## 시작하기

1. 이 폴더를 내 포트폴리오 레포 안 아무 곳에 풉니다. **레포**는 포트폴리오 파일을 모아 둔 git 폴더입니다.
2. Claude Code(AI 코딩 도구)를 열고 이렇게 말합니다.

   > `<푼 폴더>/AI-GUIDE.md` 읽고 이 레포에 이식해 줘.

   **이식**은 AI가 이 키트를 내 레포에 맞춰 설치하는 일입니다.
3. AI가 원천 자료 위치, 프로젝트 이름, 문서 말투 같은 것을 물어봅니다.
4. 이식이 끝나면 프로젝트 하나로 시작합니다.

   > `/tech-doc-issue-summary <프로젝트 폴더>`

AI용 설명 전체는 [AI-GUIDE.md](AI-GUIDE.md)에 있습니다.

## 알아 두면 좋은 것

- **AI는 원천 자료에 없는 내용을 지어내지 않습니다.** 근거가 없는 칸은 비워 두고 나에게 묻습니다.
- **AI는 내 문서를 마음대로 고치지 않습니다.** "반영해 줘", "고쳐 줘"라고 한 범위만 고칩니다.
- **정리 파일은 공개하지 않습니다.** 날짜·출처·내 답 원문이 그대로 남기 때문입니다. 공개하는 것은 기술문서뿐입니다.
- **한 번에 한 프로젝트씩** 합니다. 앞 프로젝트에서 정한 방식이 다음 프로젝트로 이어집니다.
- `examples/`의 파일은 실제 작업 기록입니다. 형식을 참고하는 데만 씁니다.
