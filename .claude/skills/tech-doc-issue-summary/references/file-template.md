# 분류 파일 골격과 표기

본보기: `report/고민-분류/WGO.md`(4차 반영본). 파일은 Obsidian에서 읽습니다. 표는 가로로 넓으면 보기 나쁘다는 피드백이 있었으므로, 고민 목록은 표 대신 콜아웃 상자로 씁니다(대응표·커버리지 표는 유지).

## 1. 파일 순서

답할 것이 맨 앞에 오게 합니다(2026-11-16 피드백: "5, 6같이 중요한걸 오히려 먼저 나에게 보여줄 수 있도록", "굳이 나누지 말고").

```markdown
# <프로젝트> — 고민 원본 1차 분류 (<날짜>, 사용자 답 반영 <날짜> 1차·2차…)

> 이 파일은 완성 기술 문서가 아닙니다. 원천 자료에서 고민·판단·시행착오를 찾아 분류하고, 각 주장이 원천의 어디에서 왔는지 대응시킨 1차 정리입니다.
> 원천에 없는 내용은 지어내지 않았습니다. 사용자 답은 새 출처로 다루고 `사용자 답 (날짜)`으로 표시했습니다.
> 지금 답이 필요한 칸은 `🟡 구체화 필요 (Q-번호)`, 나중으로 미룬 칸은 `⏸ 보류 (Q-번호)`입니다. 둘 다 §1 상자에 고민별로 모았습니다.

## 1. 먼저 볼 것 — 고민별 질문과 상태
> [!info] 읽는 법 …
> [!summary] <날짜> N차 반영 요약          ← 최신 차수만 펼침
> [!summary]- <날짜> N-1차 반영 요약       ← 지난 차수는 접힘
### 1-1. 답이 필요한 고민 — 우선순위 높음
### 1-2. 답이 필요한 고민 — 우선순위 보통
### 1-3. 보류만 남은 고민
### 1-4. 끝난 고민 (남은 질문 없음)

## 2. 나중에 확인할 목록 (보류)
## 3. 면접 대비 취약점 목록
## 4. 원천 별칭과 읽는 법
## 5. 조사 개요            (조사한 자료 / 조사하지 못한 자료와 이유 / 결과 수)
## 6. 고민별 1차 정리       (고민마다 아래 2절 템플릿)
## 7. 원본 자료 커버리지    (7-1 원본 → 고민 / 7-2 TD에만 있고 원천 근거 없는 주장)
## 8. 이후 기술문서 원본 자료 정리 계획
### 단계 A. 원본 보존과 분류 수정
### 단계 B. 고민별 판단 과정 정리
### 단계 C. 누락된 근거 보강
### 단계 D. 원본 자료 구조 제안
### 단계 E. 포트폴리오 활용 계획   (L3 후보 | 보여 줄 역량 | 필요한 자료 | 지금 설명할 수 없는 부분)
### 사용자 피드백을 반영해야 할 결정
### 필요한 사진 자료 목록         (고민 | 필요한 사진·영상 | 받쳐 줄 칸 | 구할 곳 (제안) | 우선)
```

1차 정리 때는 1-3·1-4가 비어 있을 수 있습니다. 차수 요약 상자는 1차 답 반영부터 생깁니다.

## 2. §1 고민 상자

답이 필요하면 주황 `[!warning]`(펼침), 지금 답할 것이 없으면 파란 `[!note]-`(접힘). 제목은 §6 절로 가는 링크입니다.

```markdown
> [!warning] [[#HP-D-004. 공격 사이클 구조|HP-D-004 · 공격 사이클 구조]]
> **L2** · 충실도 일부 부족 · TD §3.3 반영, 원래 고민은 누락
> - 🟡 **Q-07 (높음)** <무엇을 답하면 되는지 한 문장>. 볼 곳: `R3:L40-52`(당시 메모), TD §3.3 둘째 문단. 답할 것: (가) … 였나 (나) … 였나, 또는 다른 이유. 기억나는 만큼만.
> - **현재 상태:** <채워 둔 칸 요약, 원천↔TD 충돌은 [충돌 유지], TD 안의 모순은 [TD 내부 모순]>

> [!note]- [[#HP-D-010. …|HP-D-010 · …]] ⏸
> **L1** · 충실도 충분 · TD 누락
> - ⏸ **Q-12** <보류 이유 한 줄>(§2).
> - 옛 Q-03 풀림 (날짜 N차): <한 줄 요약>
```

- 첫 줄: `**L?** · 충실도 … · TD 반영 상태`. Level이 바뀌었으면 `**L1 (옛 L2)**`.
- 보류만 남은 상자 제목 끝에 ⏸.
- 질문을 쓰는 법은 `questions-and-dialogue.md` §1.

## 3. §6 고민 항목 템플릿

```markdown
### HP-D-001. <고민 제목>

- **분류:** Level 2
- **분류 이유:** <이 고민이 무엇에 영향을 줬나, 원천에 어떤 단계가 있나>
- **자료 충실도:** 일부 부족 — <무엇이 없나>
- **TD 반영:** §x.y 반영 / 축소 / 누락 / 원천과 다르게 씀

#### A. 현재 파악한 흐름 (Level 2 칸)

1. **문제 상황·목표:** …
2. **제약 조건:** …                       ← 근거 없으면 억지로 묻지 않음
3. **고려한 대안 (원천 그대로):** …
4. **최초 판단과 선택 이유:** …
   - 💬 사용자 답 (2026-11-16 2차): “원문 그대로”
   - 정리: <답을 어떻게 읽었나>. <해석은 (추론)>
5. **적용한 방법:** …
6. **예상과 실제 결과:** …
7. **실패·새 문제:** …
8. **판단 변경과 재시도:** 시도 1 → 시도 2 …   ← 시행착오는 시도별로
9. **최종 결과의 장단점:** …
10. **개선 방향과 배운 점:** …
- **L3 — 문제의 중요성:** …              ← L3만
- **L3 — 개발자가 직접 내린 판단:** …
- **L3 — 강조할 수 있는 역량:** … (추론)

#### B. 원본과 정리 내용의 대응표

| 단계 | 1차 정리 내용 | 원본 위치 | 원본 핵심 내용 | 대응 상태 |
|---|---|---|---|---|
| 문제 | 느린 핑 | `R2:L117` | “만약 핑 느려터져서 …” | 명확 |
| 선택 과정 | 결정자 = 본인 | 사용자 답 (2026-11-16 2차) | “내가 최종으로 정했고 …” | 명확 (사용자 답) |
| 결과 | 20/10 Hz | `TD:L117` | “…” | 미확인 (V-02) |

#### C. 누락 및 충돌

- **[충돌]** …  · **[누락]** TD에 없음 …  · **[축소]** …  · **[표현]** …
- **[풀림 2026-11-16 2차]** 옛 Q-01 …
- **[참고]** …

#### D. 추가 확인 질문

- 남은 질문: 🟡 Q-07 (§1 상자)
- 풀린 질문: Q-01 · Q-02
```

- Level 1은 A를 4칸(`문제 상황` · `선택한 방법과 판단 이유` · `적용 결과` · `남은 문제·배운 점`)으로 씁니다. 빈 배운 점은 "비어 있어도 되는 Level 1"로 둡니다.
- 원천에서 확인할 수 없는 단계는 억지로 채우지 않습니다. 채울 수 있는 것은 출처를 달아 먼저 채웁니다.
- 대응표 원본 위치는 `` `별칭:L줄` `` 또는 `` `별칭:L시작-끝` ``, 발췌는 “ ” 안에 원문 그대로, 중간 생략은 `…`. 이 꼴이어야 `check_quotes.py`가 검사합니다. 사용자 답 행은 위치 꼴이 달라 검사에서 빠집니다.

## 4. 표기 모음

| 표기 | 뜻 |
|---|---|
| `🟡 구체화 필요 (Q-번호)` | 지금 답이 필요한 칸 |
| `⏸ 보류 (Q-번호)` | 사용자가 나중·후순위·별도 세션으로 미룬 칸(§2) |
| `💬 사용자 답 (날짜 N차): “…”` | 사용자 답 원문. 지우지 않음 |
| `(추론)` | 원문이 아닌 해석 |
| `(추정)` | 코드에서 짐작한 것(대화 파일) |
| `(Claude 검토)` | 사용자 요청으로 Claude가 대안을 공격적으로 따져 본 것 |
| `[충돌 유지]` | 원천·사용자 답과 TD가 어긋나고 아직 결론 없음 |
| `[TD 내부 모순]` | 기술 문서 안에서 서로 다른 말 |
| `옛 Q-05 → V-01` | 질문의 행방. 지운 번호는 다시 쓰지 않음 |
| `V-번호` | 면접 대비 취약점(§3). 기술 문서 근거가 아니라 답변 준비용 |

## 6. §4 원천 별칭표

```markdown
| 별칭 | 파일 (<원천 폴더> 기준) | 성격 |
|---|---|---|
| R1 | `회고, 질문점 총정리.md` | 본인 회고·질문 메모 |
| CSV | `…/Team_산 (3).csv` | Asana 내보내기 |
| PDF발표 | `…/최종 발표 자료.pdf` (29쪽) | 최종 발표 |
| TD | `src/<폴더>/기술문서.md` | 현재 기술 문서, 대조 대상 |
```
읽는 법 목록: 위치 표기, 발췌 규칙, PDF 추출 한계, 대응 상태 정의, 사용자 답 표기, 옮기지 않은 개인정보.
같은 별칭 → 절대경로를 `report/고민-분류/<접두어>-alias.tsv`(별칭<TAB>경로, UTF-8)에 둡니다.

## 7. INDEX.md

`report/고민-분류/INDEX.md`는 여러 프로젝트의 목차입니다.

- 진행 상태 표 한 행: `| 프로젝트 | 파일 | 원천 폴더 | 상태 | 고민 수 (L3·L2·L1) | 구체화 필요 지점 |`. 상태 칸에 차수 이력, 마지막 칸에 남은 질문·보류·취약점 수.
- 공통 규칙 절: ID 접두어, 🟡·⏸ 규칙, 먼저 채우고 질문, L1 → 취약점, 사용자 답 = 새 출처, 정확한 일자, 위치 형식, 조사 범위.
- 프로젝트 요약 절: L3 표(ID · 제목 · 충실도), 차수별 반영 요약(최신이 위), 원천·사용자 답과 TD가 어긋나는 곳, 기술 문서에서 빠진 원천 고민 예.
