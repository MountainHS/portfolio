# 준비 단계 — 고민 분류 전에 원천을 모으고 초안을 세우기

출처: 2026-11-09~11-11 세션(WGO 원천 소스 작성, Hive `/portfolio-intake` → 재료집 → 맥락집 → 초안, Hive 고민점 문서 대조)과 그 report(`report/WGO/2026-11-09-*.md`, `report/archive/5-hive-purge-이전기록.md` 「2026-11-11 고민점 문서 대조」), 프롬프트 파일 `tech-doc-source-old/tech-doc-source-prompt.md`.

고민 분류(1~7단계)는 **프로젝트 문서 초안이 이미 있거나, 원천 폴더가 정해져 있을 때** 시작합니다. 둘 다 없으면 이 파일의 준비 단계를 먼저 합니다. 준비 단계에서 생긴 질문·답·대조표는 고민 분류 1단계의 원천 후보가 됩니다.

## 0. 어느 길로 갈지

| 지금 상태 | 길 | 결과물 |
|---|---|---|
| 코드 레포와 거친 개인 노트만 있음 | A. 원천 소스 초안 | `tech-doc-source.md` + 근거 report |
| 레포가 크고 사용자가 기억을 끌어내야 함 | B. 재료집 → 맥락집 → 초안 | `_intake/재료집.md`·`맥락집.md` → 프로젝트 문서 초안 |
| 초안은 있는데 "고민이 많이 빠졌다"는 느낌 | C. 노트 ↔ 문서 대조 | 대조표(①②③) + 넣을 자리 제안 |
| 초안과 원천이 다 있음 | 고민 분류 1단계로 | `report/고민-분류/<폴더>.md` |

A·B를 한 프로젝트에 둘 다 쓸 수도 있습니다. C는 A·B 뒤에 한 번 더 하는 검증입니다.

## A. 원천 소스 초안 (WGO 방식)

프로젝트 하나 = 세션 하나. 프롬프트 파일을 주고 "이 지침대로 <프로젝트> 기술 문서 소스를 만들어 줘"로 시작합니다. 견본 프롬프트는 키트의 `templates/source-draft-prompt.md`입니다.

1. **읽을 자료부터 묻습니다(역질문).** 파일을 열기 전에 목록만 만듭니다: `경로 | 종류 | 크기 | 추천(읽음/건너뜀) | 이유`. 같은 파일은 크기·바이트로 묶습니다. 키·비밀번호·팀원 개인 평가 파일은 "건너뜀"으로 추천합니다. "어떤 파일을 읽을까요?"로 턴을 끝내고, 고른 것만 읽습니다.
2. **뼈대는 강사 틀(`format/02-tech-document.md`)과 저장소 근거로 Claude가 세웁니다.** 개인 노트는 뼈대로 쓰지 않습니다. 고민·느낌·시행착오 문장만 「고민과 선택」·「배운 점」 재료로 씁니다.
3. **모든 주장 옆에 근거를 답니다.** 코드는 `(근거: 파일:줄)`, PDF·CSV는 `(근거: 파일명 N쪽)`·`(근거: 파일명 "항목")`. 커밋 해시·메시지는 본문에 쓰지 않고 `(이력: report N)`으로 report에 모읍니다.
4. **본문 문장 바로 아래에 태그 줄을 답니다.**
   - `[개인노트 일치]` · `[개인노트 보강]` · `[개인노트 불일치]` — 노트 원문 인용을 붙임
   - `[확인 필요]` — 사용자가 답할 질문 한 줄
   - `[측정 필요]` — 무엇을 어떻게 재면 되는지
5. **문서 끝에 셋을 붙입니다.** 근거 파일 목록, 노트에서 쓰지 않은 내용과 이유, 피드백 요청 질문 5~10개.
6. 결과는 `tech-doc-source.md`와 `tech-doc-source-report.md` 두 파일. 이미 있으면 덮어쓰지 않습니다. 레포 git 상태를 바꾸는 명령은 쓰지 않습니다.

### A-2. 확인 필요 답을 Claude가 먼저 쓰기 (O/X 검토)

`[확인 필요]`·`[측정 필요]`·피드백 질문이 많으면 겹치는 것을 묶고(WGO: 17 + 5 + 10 → 21개), 항목마다 Claude가 자료로 답 초안을 먼저 씁니다. 견본은 `templates/draft-answers.md`입니다.

- `[근거]` 자료에서 확인한 사실. 틀렸으면 고쳐 달라고 합니다.
- `[추정]` 근거를 보고 짐작한 답. O/X와 한 줄만 받습니다.
- `[빈칸]` 기억에만 있는 내용. 사용자만 채울 수 있습니다.
- 사용자는 항목마다 `→ 사용자:` 줄에 `O`, `X + 고칠 내용`, 또는 빈칸 답을 씁니다.
- 반영할 때 [추정]과 답이 다르면 답이 우선이고, "초안 [추정]은 X" 꼴로 무엇이 틀렸는지 남깁니다. 이 기록이 나중에 "AI가 지어낸 것을 사람이 바로잡은" 근거가 됩니다.

이 방식이 고민 분류의 "먼저 채우고 묻기"의 원형입니다. 사용자가 0에서 쓰는 것보다 O/X가 훨씬 빠릅니다.

## B. 재료집 → 맥락집 → 초안 (Hive 방식)

레포가 크면 `/portfolio-intake`가 재료집(질문지)을 만듭니다.

1. **범위는 사용자가 좁힙니다.** 예: "정리된 노트 바탕으로 중요한 스크립트, 에셋(머티리얼·셰이더·일부 프리팹)만 참고해서 추출해줘". 레포 전체를 훑지 않습니다.
2. **재료집**: 사용자가 각 질문 아래에 답합니다. 기억이 안 나는 곳에는 "커밋 추적해서 역질문해봐"라고 답할 수 있습니다. 그러면 Claude가 커밋·`파일:줄`을 근거로 "이 커밋에서 이렇게 바꿨는데, 이유가 ①이었나요 ②였나요?" 꼴의 역질문을 씁니다.
3. **맥락집**: 재료집 답을 반영한 뒤 남은 공백을 역질문(Hive 7개)과 고민 카드(Hive 13개)로 모읍니다. 고민 카드 = 고민 하나를 "상황 / 내가 한 것 / 빈칸" 꼴로 보여 주고 빈칸만 묻는 카드입니다.
4. **초안**: 맥락집 답이 끝나면 프로젝트 문서 §0~§5 초안을 씁니다.
5. **단계마다 새 세션입니다.** 사용자가 파일에 답을 다 달면 "새 세션에서 이어서 진행해줘"로 넘깁니다. 브리프에는 파일 위치·어디까지 답했는지만 넣습니다.

## C. 노트 ↔ 문서 대조 (Hive 방식, 읽기 전용)

초안이 나온 뒤 사용자가 "intake에서 놓친 고민이 많다"고 느끼면, 사용자가 직접 정리한 고민 노트를 문서와 대조합니다. 견본은 `templates/doc-compare.md`입니다.

1. 노트의 항목에 번호를 붙입니다(R01~R42).
2. 항목마다 셋 중 하나로 판정합니다.
   - ① 이미 있음 — 어느 절인지
   - ② 있지만 뜻이 줄거나 바뀜 — 원래 뜻과 지금 문장을 나란히
   - ③ 없음
   - (대조 대상 아님 — 팀원 담당·할 일 목록 등, 이유 한 줄)
3. 맨 위에 「한눈에」 표(판정 | 개수 | 번호)를 둡니다.
4. ②·③은 "넣는다면 어느 절에, 어떤 형태(새 절·기존 문장 보강·표 행)"만 제안합니다. 넣을지는 사용자가 정합니다.
5. 사용자가 정할 것을 「먼저 정해 주세요」 번호 목록(6개 안팎)으로 맨 앞에 둡니다. 문서와 원천이 **모순**되는 것(예: 문서 "크게 걸린 곳은 없었다" ↔ 일지 "한계가 명확함")을 1번에 둡니다.
6. 따로 「intake가 놓친 지점」 목록을 만듭니다. 재료집·맥락집에 질문이 없었던 주제입니다. 다음 intake 질문을 고칠 재료가 됩니다.
7. 이 단계는 **읽기만** 합니다. 다른 세션이 문서를 고치는 중일 수 있으므로 문서·data·스킬을 고치지 않습니다. 절 번호가 또 밀려도 찾을 수 있게 절 제목 낱말을 같이 적습니다.
8. 사용자는 번호로 답합니다("1. 한계가 명확한 게 맞아 … 4. 빼도 되고 5. 라운드 유형만"). 반영 세션은 먼저 `git diff`로 사용자가 직접 고친 줄을 찾아 건드리지 않습니다.

## 준비 단계에서 자주 생긴 일

- **Claude가 만든 자료를 사실로 쓰는 실수.** 재료집·촬영 목록·`code/` 사본은 단서일 뿐입니다. 문서의 주장은 저장소 원본에서 다시 확인합니다. 사용자 결정 기록(`결정할것.md`·피드백 목록)은 사실로 쓰고 다시 묻지 않습니다.
- **기술 문서 본문에 출처가 보이는 문제.** 사용자: "제발 관련 절 위치는 빌드 때 꼭 안보여야해. … 이게 무슨 논문 출처 같은 것도 아니고". 근거 표시는 원천 소스·report에만 두고, 프로젝트 문서로 옮길 때 지웁니다(문서 안 절 번호 각주는 예외, `portfolio-writing.md` 규칙 7).
- **모르는 규칙을 Claude가 혼자 만들려는 것.** 사용자: "어떤 규칙을 추가한다는거야?" 규칙을 더하려면 무엇이 왜 필요한지 먼저 설명합니다.
- **자는 동안 진행.** 사용자가 "자고 있으니까 자율적으로 진행하고 report에 남길것"이라고 하면, 묻지 않고 진행하되 판단한 곳을 모두 report 「확인해 주세요」에 남깁니다.
