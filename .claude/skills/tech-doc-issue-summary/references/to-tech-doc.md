출처: 세션 "WGO 고민 분류를 프로젝트 문서에 반영하고 빌드"(2026-11-16)와 커밋 `a06ef2c`의 `src/4-wgo/기술문서.md` 변경. 사용자가 "프로젝트 문서에 반영해 줘"라고 했을 때만 합니다(루트 `CLAUDE.md` 원칙 2의 "고쳐 줘").

## 근거 규칙

- 근거는 분류 파일의 사용자 답(💬 줄·대응표 `사용자 답` 행)과 원천 발췌뿐입니다. 새 사실·수치·의도는 만들지 않습니다.
- `(추론)`·`(추정)`이 붙은 내용은 프로젝트 문서에 사실로 쓰지 않습니다. 쓰고 싶으면 report 「확인해 주세요」에 남깁니다.
- ⏸ 보류 고민은 답이 없는 부분을 비워 둡니다. V-취약점은 넣지 않습니다(답변 준비용).
- 원천과 프로젝트 문서가 충돌하면 분류 파일의 결론을 따릅니다. 결론이 없으면 고치지 않고 report에 적습니다.
- 고민과 무관한 줄은 고치지 않습니다. 사용자가 직접 고친 줄은 먼저 `git diff`로 찾아 글자 그대로 둡니다.
- 프로젝트 문서 본문에 넣지 않는 것: 정확한 일자(상대 시점 "1차 빌드", "마지막 스프린트"로), 커밋 해시·메시지, 원천 자료를 가리키는 `(§4.4)`·`회고.md:12`·`R2:L92`·`Q-49` 같은 출처. 근거는 report의 반영 목록 "근거" 열에만. 문서 안 상호 참조 `(6.3-1)`·`` (`code/X.cs:44`) ``는 넣어도 되고(상세 문서 링크·슬라이드 숨김, `portfolio-writing.md` 규칙 7), 번호가 밀리면 맞춥니다.
- 문체는 지금 프로젝트 문서를 따릅니다(WGO는 "~다" 평서체). `.claude/CLAUDE.md` 「글쓰기 기본 지침」(핵심 먼저, "A가 아니라 B" 금지, 목적 절에 구현 금지)과 `.claude/rules/portfolio-writing.md`를 지킵니다.

## 옮길 때 자주 틀린 것 (11-16~11-26 교정)

- **문서 문장이 코드와 다르면 고치기 전에 묻습니다.** 예: 문서 "정상 종료 핸드셰이크 후 정리" ↔ 코드는 응답을 기다리지 않음. 사용자 답에 따라 "Close 알림을 보낸 뒤 바로 정리"로 고쳤습니다. 사용자가 그 낱말을 다른 뜻으로 썼을 수 있습니다.
- **틀(대안 A/B)을 Claude가 씌우지 않습니다.** 사용자가 문서를 쓰며 떠올린 방안이면 "문서를 쓰며 떠오른 방안" 소제목으로 쓰고, 그 방안과 기존 방식의 타당성을 근거와 함께 따로 검토해 report에 둡니다.
- **맥락 없는 구절을 옮기지 않습니다.** 분류 파일의 한 구절만 떼어 넣으면 독자가 "어디서 나온 말인지" 모릅니다. 문서에 들어가는 문장은 그 절 안에서 앞뒤가 이어져야 합니다.
- **사실(기간·차수·날짜)은 원천을 다시 열어 확인합니다.** 분류 파일의 요약만 믿고 옮기다 스프린트 주기·발표 날짜를 틀린 사례가 있습니다.
- **그림·다이어그램은 실제 페이지에서 봅니다.** 상세 문서(`doc.html`)와 슬라이드 둘 다. 컨테이너 폭 때문에 gantt가 작아진 사례가 있습니다.
- **슬라이드에만 쓰일 문구도 근거가 없으면 지웁니다.** 사용자: "엄격한 수립 필요 이거 없애 버려" / "이건 후순위야. 취약점으로 남겨놔."

## 순서

1. 규칙 파일·분류 파일(§1·§6·§8)·대화 파일·`INDEX.md`를 읽고, `git diff`로 사용자가 고친 줄을 찾습니다.
2. 프로젝트 문서를 앞쪽 절부터 고칩니다. 절을 옮기면 번호와 본문 상호 참조를 함께 맞춥니다.
3. 사용자가 고친 줄이 그대로인지 grep으로 확인합니다.
4. `/portfolio-build <폴더>` → `deck-edits.py apply --all` → `python .claude/skills/portfolio-build/portfolio-edits.py apply --all`.
5. `/portfolio-edit`로 고정(pin)한 장면이 바뀐 내용과 맞지 않으면 되돌리기를 권하고, 사용자 승인 뒤에만 합니다.
6. 편집 서버로 세 페이지를 점검합니다(빨간 띠·식별자 끊김, `.claude/rules/portfolio-writing.md` 「렌더 검수 방법」).
7. `report/<폴더>.md` 맨 위 "이제 할 일"에: 반영 목록(고민 ID · TD 절 · 근거 `별칭:L줄`·Q-번호), 비운 곳(보류·추론이라 뺀 것), 「확인해 주세요」(사용자 답을 Claude가 문장으로 옮긴 곳), 촬영 요청(§8 사진 목록). 루트 `report.md`는 요약판으로 다시 씁니다.
8. 커밋하지 않습니다(요청 때만).
