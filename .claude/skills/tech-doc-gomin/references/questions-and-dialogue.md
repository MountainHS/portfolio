출처: WGO 1~4차 답(`report/고민-분류/WGO.md`의 💬 줄), 대화 세션 "WGO Q-22 종료 방식·토큰 대화 정리"·"WGO 고민 Q-16·Q-18 대화 정리"(2026-11-16).

## 1. 질문 쓰기

### 규칙

- **먼저 채우고 묻습니다.** 참고 범위 문서에 형식 칸에 맞는 내용이 있으면 채운 뒤, 남은 것만 묻습니다.
- **무엇이 부족한지 구체적으로.** 볼 원천(별칭:L줄·TD 절)과 답할 내용을 적습니다. "원천에 없음"만 쓰지 않습니다.
- **예시 선택지를 붙입니다.** (가)/(나) 갈림길, 또는 기억을 끌어낼 예("예: 나가기 버튼을 눌러도 메인 화면으로 안 넘어감, 서버에 그 플레이어가 남음, 다른 사람 화면이 멈춤"). 후보가 Claude 추론이면 "제가 추론한 후보이니 참고만 해 주세요".
- **수준이 여럿이면 후보 표.** 예: 명세 수준 ①경우별 책임 / ②데이터 계약 / ③상태·시점 표 + "객체마다 달라도 됩니다. '플레이어는 ①, 물고기는 ②까지'처럼 답하셔도 됩니다."
- **이미 답한 것은 다시 묻지 않습니다.** 분류 파일·`report/<폴더>.md`·`_intake/` 답을 먼저 찾습니다.
- **Claude가 찾을 수 있는 것은 먼저 찾습니다.** 범위 안 자료(PDF·CSV·일지)에 있을 법하면 직접 확인한 뒤 묻습니다. 범위 밖이면 "어디를 봐도 되는지"를 묻습니다.
- **사소한 L1은 묻지 않고 취약점(V-번호)으로.**
- **우선순위 표시:** 높음 = 중요한 고민의 최초 판단 근거 부족, 원본과 정리 사이 의미 차이, 자료 모순, 주요 시행착오 누락 가능성, L2/L3 분류 애매. 보통 = 검증 결과 필요, 개선 방향 없음, 묶을지 결정. 낮음 = 표현·제목·디자인(거의 묻지 않음).
- **부담 낮추기:** "기억나는 만큼만, '모르겠음'도 괜찮습니다."
- **코드가 크면 역질문으로.** 코드 전체를 읽지 않고 "이 판단이 들어간 코드가 어느 파일·함수인지 알려 주시면 그 범위만 보겠습니다"처럼 묻습니다.

## 2. 답 반영 체크리스트 (차수마다)

1. 사본: `%TEMP%\gomin\<이름>.before-sN.md`.
2. 답 찾기: 탭 들여쓴 줄(`grep -n $'^\t\|^> \t\|^>\t'`) 또는 사본 diff. 바로 위 `**Q-번호**`로 짝을 맞추고 줄 수를 셉니다. 채팅으로 답하면 사용자가 Claude 글을 `>` 인용하고 그 아래에 답합니다(`<!-- reply N -->` 블록마다 따로 반영).
3. 사라진 상자·제목 줄이 있으면 사본에서 되살리고 맨 먼저 알립니다.
4. 코드 확인: 답 원문이 허락한 범위만("…`RoomClient.cs` 확인하고 필요하면 더 참조해봐" → 부르는 쪽 한 단계까지). 범위 밖은 읽지 않고 "읽어도 되면 확인하겠습니다". 읽은 범위는 차수 요약에 파일·함수 단위로.
5. §6 A: 정리 문장 + `💬 사용자 답 (날짜 N차): “원문”`. 짧거나 애매한 답은 "…로 읽었습니다"를 쓰고 필요하면 확인 질문을 새로.
6. §6 B: `| 칸 | 요지 | 사용자 답 (날짜 N차) | “원문” | 명확 (사용자 답) |`. 코드로 확인했으면 `명확 (코드 확인: 함수 이름)`.
7. §6 C: `[풀림 날짜 N차]`, TD에 빠진 것은 `[누락]` + 다듬을 때 넣을 후보.
8. 🟡 정리: 풀린 것 지움, 새 Q는 이어 번호, 보류는 ⏸ + §2 한 줄(사용자 원문·확인할 때 볼 것).
9. Level·충실도 변경과 이유 한 줄. 추정을 지우면 C에 지운 까닭과 요지.
10. §1 재배치(높음 → 보통 → 보류만 → 끝남), 차수 `[!summary]` 추가(답 줄 수 · 풀린/보류/새 질문 · 남은 수 · Level·충실도 변경 · 읽은 코드 범위 · 새로 모은 것), 지난 차수는 `[!summary]-`.
11. §3·§5 결과 수·§7·§8(결정·사진 목록)·`INDEX.md` 맞추기.
12. 검사: `check_quotes.py` 불일치 0, 🟡·⏸ 번호가 §1과 일치, `[[#…]]` 링크 살아 있음, 답 원문이 💬 줄에 남아 있음.
13. 보고: 위 수치 + 「애매했던 줄」 + 허락이 없어 하지 않은 것.
14. 컨텍스트가 커지면 사용자가 "새 세션에서 이어서"라고 합니다. 다음 차수 세션을 fresh로 열고(브리프: 파일 위치·몇 차까지 했는지·이 체크리스트) 바로 연결을 끊습니다.

## 3. 대화 세션 (티키타카)

사용자가 “이건 따로 세션 파서 같이 티키타카하면서 해야할거 같아. 진짜 까먹었음.”처럼 말한 질문을 푸는 별도 세션입니다.

### 여는 쪽 브리프

```
배경: <프로젝트 한 줄>, 분류 파일 위치, 몇 차까지 반영, 이 질문이 왜 대화로 왔는지(사용자 원문).
진행 방식: 사용자는 당시 내용을 잊었습니다. 코드를 함께 보며 묻고 답합니다("티키타카"). 혼자 결론 내지 않습니다.
정리할 것: ① … ② … ③ …
먼저 읽을 것: 분류 파일 §6 <고민> A칸, §1 상자, 관련 Q 번호.
볼 코드 범위: <폴더·함수> (모르면 "사용자에게 물어 받은 범위만").
진행 규칙: 한 번에 질문 1~2개. 코드 조각을 보여 주고 "여기서 이렇게 하는데, 당시 이렇게 한 이유가 기억나나요?"처럼 묻기. 사실·기억·해석을 나누고 (추론)/(추정) 표시.
결과: <접두어>-Q<n>-대화.md 에만 씀. 분류 파일 반영은 요청 시, 직전에 다시 읽고 해당 절만.
제약: 커밋 금지, Git·다른 report는 허락 없이 읽지 않음, 경어체, "A가 아니라 B" 꼴 금지.
```
`start_session` 뒤 전역 규칙대로 `detach_session`. 브리프에 Claude가 쓴 결과물을 이 세션으로 가져오지 않습니다.

### 대화 쪽 진행

- 첫 턴: 코드를 읽고 결과 파일을 먼저 만들어 「코드에서 본 사실」을 **[코드]** 줄로 적은 뒤 첫 질문.
- 매 턴: 정리한 줄기 → 짐작한 것 `(추정)` → 겹쳐 보이는 것 `(추론)` → 다음 질문 1~2개.
- 답이 모호하면(“or”) 지어내지 않고 미확인. 답이 코드와 어긋날 수 있으면 코드를 다시 보고 취약점 후보로 따로.
- 사용자가 "공격적으로 검증해 줘"라고 하면: 결론 먼저 → 약점을 근거와 함께 → "기술 문서에 쓸 흐름 (추론)". 결과는 `(Claude 검토)` 표시.
- 기술 문서는 사용자가 “여기서 고쳐”라고 한 칸만 고치고, 넣지 않은 것(추정·해시·일자)을 밝힙니다.
