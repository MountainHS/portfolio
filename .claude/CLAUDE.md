# 이 포크만의 규칙

> 루트 `CLAUDE.md`는 `/portfolio-update`가 템플릿 원본으로 바꿉니다. 이 파일(`.claude/CLAUDE.md`)은 업데이트가 건드리지 않으므로, 이 포크에서만 쓰는 규칙은 여기에 둡니다.

## 루트 CLAUDE.md 요약본

- 루트 `CLAUDE.md`는 `.claude/settings.json`의 `claudeMdExcludes`로 시작 문맥에서 뺐습니다(2026-11-26). 대신 `.claude/rules/template-core.md`(요약본, 항상 로드)와 `.claude/rules/template-preview.md`(「미리보기」 절 그대로, 렌더러·데이터·테마 파일을 다룰 때 로드)가 실립니다. 세부가 필요하면 루트 파일을 직접 Read합니다.
- **`/portfolio-update` 뒤에는 반드시** `git diff <이전 커밋> -- CLAUDE.md`로 루트 변경점을 보고, 바뀐 원칙·명령·폴더는 `template-core.md`에, 「미리보기」 절 변경은 `template-preview.md`에 반영한 뒤 요약본 머리의 기준 커밋을 고칩니다. 반영 내용을 사용자에게 한 줄씩 알립니다.

## 호칭

- 사용자를 '학생'·'수강생'으로 부르지 않고 '사용자'·'너'로 부릅니다(2026-11-09 사용자 요청). 루트 `CLAUDE.md`·템플릿 스킬 원문이 '수강생'이라고 써도 답변·report·세션 브리프에서는 따르지 않습니다. 템플릿 원문은 고치지 않습니다.

## 글쓰기 기본 지침

- 독자는 채용 담당자·팀장, 화자는 사용자 본인(1인칭, **합니다체**). 핵심 먼저, "A가 아니라 B" 금지, 목적 절엔 경험·의도만.
- 전문은 `.claude/rules/portfolio-writing.md` 「글쓰기 기본 지침」에 있습니다. `src/`·`data/`·`report/`·`format/`·포트폴리오 스킬 파일을 다룰 때 자동으로 실립니다. 그 전에 문서 글을 쓰거나 고치게 되면 먼저 그 파일을 Read합니다.

## report 구조

- **루트 `report.md` = 요약판.** 사용자가 오랜만에 오거나 정신없을 때 이것만 보고 다시 시작할 수 있게, 다음 네 절만 짧게 씁니다.
  1. 마지막으로 한 일 (날짜, 커밋 여부)
  2. 다시 시작할 때 할 것 (3줄 안팎, 어느 프로젝트의 어느 작업 파일을 보면 되는지)
  3. 리마인드 — 메모리와 report 보관 파일(예: `report/3-mini-ftl/2026-11-26-나중에-할-일-보관.md`)에 "나중에 하기로 한 것"으로 남은 일(시연 영상·기간 보완·블로그 링크 등)
  4. 프로젝트별 report 표 (파일 경로 · 한 줄 상태)
- **`report/<src 폴더 이름>.md` = 프로젝트별 메인 report(사람이 보는 곳).** 맨 위 자동 목차(「✍ 내가 할 일」 상자 + 작업 기록 링크) + 짧은 머리글(미리보기 주소·질문 목록)만 둡니다(2026-11-26). 원천 자료 폴더(`tech-doc-source-old/` 등) 옆 report에는 새 내용을 쓰지 않습니다(2026-11-09: 사용자가 그 report를 원천 자료로 착각함).
- **작업 하나 = 파일 하나: `report/<src 폴더 이름>/YYYY-MM-DD-<작업>.md`.** 첫 줄 `# YYYY-MM-DD <작업> (커밋 여부)`, 둘째 줄 `메인: [[<이름>]]`. 할 일·"확인해 주세요"·결정 기록·점검 결과는 이 파일에 씁니다. 같은 작업을 이어 하면 그 파일에 덧붙이고, 다른 작업이면 새 파일을 씁니다.
  - 새 파일을 쓰거나 제목을 바꾼 뒤 `python tools/report-toc.py report/<이름>.md`로 메인 목차를 다시 만듭니다. 메인을 손으로 고치지 않습니다(질문 목록 제외).
  - 다음 세션은 메인 목차(`Read limit 40`)를 보고 필요한 작업 파일 하나만 읽습니다. 작업 파일이 길면 `Grep -n "^## 제목"` 뒤 `offset/limit`.
  - 옛 한 파일 report(절로 쌓은 것)는 `report-toc.py --split`으로 나눕니다(Hive·WGO·Mini FTL은 2026-11-26에 나눔).
- **질문은 한 곳에만 둡니다.** `report/` 안의 모든 파일(프로젝트별·여러 프로젝트를 묶은 계획 report 모두)에서, 사용자에게 묻는 줄은 메인 맨 위 목록 한 곳에만 쓰고 각 질문 바로 아래에 빈 답 줄을 둡니다. 작업 파일에 같은 질문을 다시 쓰지 않습니다(2026-11-22 `피드백-반영-계획.md`에서 답 달 자리를 못 찾음).
  - 답 = 질문 바로 아래 들여쓴 줄. 체크박스가 비어 있어도 답이 있으면 푼 질문으로 셉니다(재료 점검표 포함). "자료 없음"으로 적기 전에 메인 report 질문 목록과 `report/고민-분류/INDEX.md`를 봅니다.
  - 사용자는 report를 옵시디언(Obsidian)으로 읽습니다. "A~E 중 무엇"처럼 본문을 봐야 답할 수 있는 질문에는 `[[#본문 제목]]`(같은 파일)이나 `[[파일#제목]]` 링크를 달고, 링크 대상이 되도록 본문 선택지에 제목(`####`)이나 블록 id(`^q1-a`)를 둡니다(2026-11-22: 질문만 보고 본문을 찾아 스크롤하느라 번거로움).
- `report/`와 `report.md`는 둘 다 `.gitignore`에 있어 공개되지 않습니다.
- **큰 파일은 통째로 읽지 않습니다**(2026-11-26, 토큰 분석: 같은 report·문서 전체 재읽기가 한 주 90회+). 나누지 않은 report(`고민-분류/`·자소서·계획)는 맨 위 `<!-- toc:start -->` 목차만 `Read limit 40`으로 보고 필요한 절을 Grep으로 찾아 읽습니다. 「이전 기록」이 커지면 `report-toc.py --archive`. 고친 뒤 확인도 고친 절만. 프로젝트 문서(`src/*/기술문서.md`)도 같습니다.
- **사용자가 할 일은 제목에 `✍`를 붙인 작업 파일(또는 절)로만 씁니다**(2026-11-26: 작업 기록 속에 섞인 할 일을 사용자가 못 알아챔). 메인 목차 맨 위 「✍ 내가 할 일」 상자에 자동으로 모입니다.
  - 작업 기록 본문에 "사용자가 할 것"을 섞지 않습니다. 따로 `YYYY-MM-DD-<할 일>.md`(제목 `# ✍ <할 일> (날짜)`)를 만들고, 기록 파일에는 그 링크만 둡니다.
  - 끝났거나 다른 방식으로 해결된 할 일은 제목의 `✍`를 `✔`로 바꾸고 목차를 갱신합니다. 상자에는 남은 일만 보여야 합니다.
  - 답이 끝나면 그 턴 마지막 메시지에 새로 생긴 `✍` 할 일 이름을 알립니다.

## 그림·영상 확인 (토큰 절약)

이미지는 한 번 Read하면 세션이 끝날 때까지 매 호출에 다시 실리고, 처음 들어올 때 캐시 쓰기(정가 1.25~2배)로 계산됩니다(2026-11-26 측정: 한 주 이미지 Read 403회, 같은 프레임을 4~6번 다시 엶).

- **숫자 검사 먼저, 그림은 마지막 1장.** 슬라이드·페이지는 `PFScene/PFPage/PFDoc.report()`·`tools/check-deck.mjs`, 영상은 프레임 시각·길이·자막 검사기 결과로 먼저 판정합니다. 그림은 숫자로 판정할 수 없는 것(색·겹침·느낌)만, 고친 뒤 마지막에 한 번 봅니다.
- **여러 장은 한 장으로 모아 한 번에.** 프레임·장면 여러 개는 접촉 시트 한 장으로 만들어 한 번 Read합니다. 같은 그림을 다시 열지 않고, 처음 볼 때 확인할 점을 텍스트로 적어 둡니다.
- **그림 작업과 글 작업은 세션을 나눕니다.** 사진·간트·다이어그램·영상 수정이 끝나면 결과를 report에 텍스트로 적고, 이어지는 글 작업은 새 세션에서 그 report 절을 보고 합니다(압축해도 이미 쓴 이미지 캐시 비용은 돌아오지 않음).
- 사용자가 그림을 보여 달라고 하면 Read 대신 `SendUserFile`로 보냅니다(내 문맥에 실리지 않음).

## 스킬이 루트 report.md를 덮어쓸 때

`/portfolio-build`·`/portfolio-check`·`/portfolio-edit`는 루트 `report.md`에 씁니다. 스킬을 고치지 않고 다음 순서로 맞춥니다.

1. 스킬을 실행하기 **전에** 루트 `report.md`의 내용이 `report/`에 다 옮겨져 있는지 확인합니다(요약판이면 그대로 두어도 됨 — 요약판 내용은 프로젝트 report와 메모리로 다시 만들 수 있음).
2. 스킬이 끝나면 루트 `report.md`에 생긴 점검 결과를 프로젝트별로 나눠 `report/<폴더>/YYYY-MM-DD-<작업>.md` 새 작업 파일로 옮기고 `report-toc.py`로 메인 목차를 갱신합니다. 이때 기존 "확인해 주세요" 줄과 사용자가 단 답(들여쓰기 줄)을 지우지 않습니다.
3. 루트 `report.md`를 위 요약판 형식으로 다시 씁니다.

## 로컬 미리보기

- `preview.cmd`(더블클릭) 또는 `.\preview.ps1 [all|portfolio|deck|doc|report|server|stop] [프로젝트 폴더]`로 엽니다. 편집 서버(`edit-server.py`, 포트 4600)를 켜고 페이지를 브라우저로 엽니다.
- 4600 포트를 `python -m http.server`가 쓰고 있으면 편집 모드가 꺼지므로 `.\preview.ps1 stop` 뒤 다시 켭니다. 사용자에게 미리보기를 안내할 때도 이 스크립트를 먼저 알려 줍니다.
- Claude 안에서는 `/local-preview [portfolio|deck|doc|all|report|server|stop] [프로젝트 폴더]`(`.claude/skills/local-preview/`)가 같은 `preview.ps1`을 불러 엽니다. 페이지 종류를 빼면(인자 없음·폴더만) 포트폴리오 페이지만 열고, 슬라이드·상세 문서는 `deck`·`doc`·`all`을 적었을 때만 엽니다(`preview.cmd` 더블클릭·`preview.ps1` 인자 없음도 같은 기본값 `portfolio`). 이름이 `portfolio-`로 시작하지 않아 `/portfolio-update`의 교체 목록 밖입니다.

## 이 포크 전용 기능 (편집 모드·슬라이드·명령 패널)

- 자세한 규칙은 `.claude/rules/fork-features.md`에 있습니다. `assets/`·`*.html`·`data/`·`edit-server.py`·`tools/`·포트폴리오·편집 모드 스킬을 다룰 때 자동으로 실리고, 그 전에 이 기능을 고쳐야 하면 직접 Read합니다.
- **`/portfolio-build`와 `/portfolio-edit` 뒤에는 반드시** `python .claude/skills/portfolio-build/deck-edits.py apply --all` 다음에 `python .claude/skills/portfolio-build/portfolio-edits.py apply --all`을 실행합니다(편집 모드에서 고친 글을 data에 다시 덮음, 멱등).
  - 이어서 `python tools/code-locations.py --all`로 슬라이드 코드 캡션의 실제 위치(`클래스.메서드() · 파일:줄`)를 다시 찾습니다(프로젝트 문서 코드 블록이나 `src/<폴더>/code/`를 고쳤을 때 필요, 멱등). 자세한 규칙은 `.claude/rules/fork-features.md` 「슬라이드 코드 캡션 위치」.
  - 실행 전에 `git status`를 봅니다. 이번 작업 밖 프로젝트의 프로젝트 문서가 `M`이면 `--all` 대신 대상 폴더만 적용하거나 사용자에게 먼저 묻습니다(그 미커밋 수정이 data에 섞임, 2026-11-22). 커밋할 때도 세션 전부터 `M`인 파일은 `git diff`로 내 변경만인지 확인합니다.
- 슬라이드는 30~40장 권장이고, `/portfolio-build`는 장면 수를 맞추려고 장면을 빼지 않습니다. 40장을 넘을 때만 리포트에 [참고]로 알립니다.

## `/portfolio-build` 실행 방식 (토큰 절약)

- 스킬 §1의 "프로젝트마다 서브에이전트를 병렬로"는 쓰지 않습니다. 새 서브에이전트는 시작 문맥과 schema·format을 각자 다시 읽어 실행 한 번에 1~3M 토큰이 더 듭니다(2026-11-12·13 측정).
- 프로젝트 1~2개 재빌드는 메인 세션에서 차례로 합니다.
- 전체(3개 이상) 빌드는 메인에서 schema·format을 먼저 읽은 뒤, 프로젝트마다 `fork` 서브에이전트(부모 문맥을 물려받음)로 나눕니다. 효과가 없으면 메인 순차로 돌아갑니다.
- `SKILL.md`는 `/portfolio-update`가 덮어쓰므로 이 규칙은 여기에 둡니다.

## 프로젝트 문서 고민 분류 (이 포크 전용)

- 프로젝트 문서 원천 자료(회고·노트·Asana·발표·일지)에서 고민을 찾아 L1·L2·L3로 나누고, 수준별 형식 칸을 먼저 채운 초안을 `report/고민-분류/`에 쓴 뒤, 질문·답 반영·대화 세션(티키타카)으로 구체화하고 프로젝트 문서로 옮기는 절차는 `/tech-doc-issue-summary <src 폴더> [시작|답 반영|대화 Q-번호|프로젝트 문서 반영]`(`.claude/skills/tech-doc-issue-summary/`)에 있습니다. WGO 작업(2026-11-12~16)에서 쓴 방식을 옮긴 것이고, 본보기는 `report/고민-분류/WGO.md`입니다.
- `src/**`·`report/고민-분류/**`를 다룰 때만 자동으로 실립니다(`paths`). 직접 불러도 첫 인자가 `src/` 프로젝트 폴더가 아니면 실행하지 않습니다.
- 이름이 `portfolio-`로 시작하지 않아 `/portfolio-update`의 교체 목록 밖입니다.
- 고민 분류 파일(`report/고민-분류/*.md`)은 §1 상태표를 먼저 읽고, 필요한 고민은 `### <고민 ID>` 제목 줄을 Grep으로 찾아 그 절만 Read합니다. 파일 전체를 처음부터 읽지 않습니다.
